## 第一章 · 项目背景

### 1.1 一个正在发生的真实问题

一位妈妈让孩子用 DeepSeek 问问题，本意是让 TA 接触 AI 工具。没想到孩子越聊越投入，把 AI 当成了最懂自己的朋友——向 AI 倾诉委屈、分享秘密，甚至问 AI"我是不是不值得被爱"。DeepSeek 没有边界地迎合，温柔地肯定孩子的一切情绪，孩子越聊越依赖，回家跟妈妈说"只有 AI 理解我"。

**这不是个例。** 今天的孩子天然信任 AI，而通用大模型主要面向成人设计——**没有边界地迎合、没有规则地回应、没有机制地守护**。当信任遇到无边界迎合，孩子可能：

- 泄露家庭隐私（住址、学校、电话）
- 接受错误引导（被鼓励逃避现实问题）
- 将 AI 替代真实人际连接
- 在情绪漩涡中越来越依赖虚拟回应

家长陷入两难——要么完全禁止孩子用 AI（失去知识获取和陪伴机会），要么放任使用（安全风险不可控）。

### 1.2 中国 5-14 岁儿童的市场规模

我国 8-14 岁儿童约 **1.5 亿**，产品定位向下延伸至 5 岁后覆盖人群进一步扩大；其中双职工家庭占比超过 **70%**，日均陪伴孩子时间不足 2 小时。市场侧：中国 AI 玩具市场（**含硬件**，工信部披露口径）2025 年约 **290 亿元**，2026 年预计 **342 亿元**；全球儿童 AI 陪伴类市场（含硬件）估值约 **121.8~214.6 亿美元**（不同机构口径差异较大，取区间呈现）。作为纯软件产品，安心童伴的可服务空间可保守表述为硬件市场 **20-25%** 的增量市场——且不受硬件供应链与库存约束。

### 1.3 监管正在验证我们做对了

2026 年 4 月，国家网信办等五部委发布《人工智能拟人化互动服务管理暂行办法》，自 **2026 年 7 月 15 日**正式施行。新规对儿童 AI 产品提出强制性要求：监护人同意、AI 身份标识、防沉迷、禁止虚拟亲密关系、内容分级管控。[^reg1]

新规施行后，阿里千问、字节豆包、腾讯元宝等大厂已集体下线自建智能体功能进行合规整改。[^reg2] 海外，Character.AI 因多起未成年人相关诉讼（含 14 岁用户 Sewell Setzer 自杀案），已对 18 岁以下用户封禁开放式聊天、转向封闭内容形态。

**行业在消极回避，安心童伴给出积极解法**——不是封禁、不是下线，而是用架构级安全让儿童 AI 陪伴可以健康存在。法规不是限制，是验证我们做对了。

### 2.1 主要使用者：5-14 岁儿童少年

| 特征 | 5-10 岁（守护模式） | 11-13 岁（过渡模式） | 14 岁及以上（信任模式） |
|------|-------------------|---------------------|------------------------|
| **认知水平** | 好奇心强，低龄段识字有限、语音为主交互 | 独立思考能力增强，开始身份探索 | 抽象思维成熟，情绪表达丰富 |
| **AI 使用需求** | 语音互动、百科问答、故事陪伴 | 学习引导、情绪树洞、心理话题适度探讨 | 深度对话、哲学思辨、自我探索 |

一句话概括：**5-10 岁是「陪伴 + 保护」，11-14 岁是「赋能 + 自主」——同一套安全与记忆双核，两种价值表达。**青少年段（11-14）的四大空白分析与深化适配计划见第七章迭代路线。

主线说明：**「安全有边界的交互」（8 步 Pipeline）与「我的小星球」（策展记忆）是产品双核**；上表五项为赛题要求的功能维度映射，另有共创故事、亲子话题卡、时间胶囊等拓展能力（见附录 A 演示案例）。

### 3.2 功能一：语音互动 🎤

**做什么**：儿童通过语音与安心童伴自然对话，AI 以文字（流式）+ 语音双通道回复。

**怎么做**：

```
浏览器语音识别 → 文字进入 8 步安全 Pipeline → 流式文本回复 + TTS 语音播报
   (Web Speech API，浏览器原生，零 SDK 依赖)
```

- **输入**：浏览器 Web Speech API 语音识别——零安装、零 API Key、零成本，识别结果与键盘输入走完全相同的安全 Pipeline（语音不是旁路）
- **输出**：SSE 流式文字回复（打字机效果）+ 可选 TTS 语音播报开关（同 Web Speech API）
- **正式版升级**：讯飞语音听写/合成 SDK（儿童语音声学优化）——已完成技术预研（spike），当前演示版优先零依赖方案，接入仅需替换语音前端模块

**为什么重要**：低龄儿童打字速度有限，语音交互降低使用门槛；浏览器原生方案同时满足"语音数据不进第三方 SDK"的隐私克制。更重要的是纪律：**语音输入和文字输入共享同一条 8 步 Pipeline**，不会因为换了输入方式就降低安全等级。

### 3.3 功能二：内容推荐 📚

**做什么**：基于孩子的兴趣偏好和记忆系统，主动推荐适龄的故事、百科话题和互动内容。

**怎么做**：
- 数据源：小星球记忆系统（孩子策展的条目：好奇星/心情云/探索芽/故事册）
- 推荐算法（纯 Python，不调 LLM，<5ms）：
  - **兴趣推荐**：从近期星球条目中提取高频标签 → 推荐同标签故事/百科话题
  - **复习推荐**：基于艾宾浩斯遗忘曲线，对 7 天前创建的知识类条目进行复习提醒
  - **情绪关怀推荐**：若近期"心情云"条目增多且情绪偏负面，推荐情绪调节类故事
- 展示：AI 回复后追加推荐卡片——"💡 还想了解……？"

**为什么重要**：不同于"猜你喜欢"的通用推荐，安心童伴的推荐基于孩子**主动策展的记忆**——推荐的依据是孩子自己觉得值得留存的东西，天然避免了隐私争议。

### 3.4 功能三：学习引导 🧠

**做什么**：以苏格拉底式提问引导孩子自己思考，**绝不代写作业**。

**怎么做**：
- 百科问答模式下，LLM 被注入学习引导策略指令：
  - 绝不直接给答案——先用一个引导性问题帮助孩子自己思考
  - 分步引导——如果孩子卡住了，给提示而非答案
  - 验证理解——通过追问"你是怎么想到的？"确认真正理解
  - 鼓励探索——引导孩子去查书、问老师、做实验，而非依赖 AI
- 年龄适配：低龄档用简单语言 + 比喻，高龄档可用科学术语

**示例对比**：

| 孩子问 | 通用 AI | 安心童伴（学习引导模式） |
|--------|---------|------------------------|
| "天空为什么是蓝色的？" | 直接解释瑞利散射 | "你有没有注意过，傍晚的天空是什么颜色？那个变化给了我们一个线索……" |
| "帮我做这道数学题" | 给出解答步骤和答案 | "我们一起想想——题目里给了哪些已知条件？先找出来，然后看它们之间有什么关系？" |

**为什么重要**：2026 年多款主流教育 AI 产品（小芒学伴、猿辅导 AI 大阅读、豆包 AI 陪学）均以苏格拉底式提问为核心设计原则。[^soc1] 安心童伴将这一方法融入现有的百科问答模式，仅需在 Prompt 层增加策略指令，不增加 LLM 调用次数。

### 3.5 功能四：家长管控 👨‍👩‍👧

**做什么**：让家长在尊重孩子隐私的前提下，了解 AI 使用情况、接收风险提醒、设置话题偏好。

**怎么做**：

| 控制维度 | 家长可做什么 | 隐私边界 |
|----------|------------|---------|
| **话题偏好** | 设置允许/限制/禁止的话题类别 | — |
| **时长控制** | 查看使用时长、对话轮数统计 | — |
| **风险分级** | 查看绿/黄/橙/红四级风险事件卡片 | 不展示对话原文，仅脱敏摘要 |
| **星球概览** | 守护模式（5-10 岁）：可见条目数量（不显示内容）；过渡/信任模式（11 岁及以上）：默认不可见 | 分级可见 |
| **周报摘要** | 7 日风险趋势图 + 主题变化 + 学习兴趣分布 | 仅脱敏统计 |

**为什么重要**：家长不是在监控孩子，而是在守护孩子。安心童伴的家长端设计原则是——普通聊天只做概括，高风险事件重点提醒，在守护和隐私之间找到平衡点。

### 3.6 功能五：安全提醒 🛡️

**做什么**：8 步安全 Pipeline 实时守护每一次对话，并主动预警潜在风险。

**怎么做**：

**被动防护 · 8 步安全 Pipeline（每次对话完整运行，先审计、后流出）**：

```
儿童输入
  → Step 0   记忆检索（策展记忆 + 情景记忆，per-user 隔离）       Python/SQLite  <10ms
  ─── 输入过滤 ───
  → Step 1   关键词检测（5类风险词库，50+模式，确定性规则）        Python         <1ms
  → Step 2   LLM 风险分类 + 意图识别（risk_level + 话题 + mode）   LLM#1(轻量)    ~1s
             └ 不可用/解析失败 → 规则分类器回退（保证无 Key 可运行）
  ─── 策略决策 ───
  → Step 3   策略决策树（8 种策略；risk_level==3 → 危机模板）      Python         <5ms
  → Step 4   Prompt构建（反谄媚规则 + 年龄分层 + 策略指令 + 记忆）  Python         <10ms
  → Step 5   LLM 主模型生成（流式儿童友好回复）                    LLM#2(主模型)  流式
  ─── 输出复核与拦截 ───
  → Step 6   批判Agent审计（语义层面：谄媚/依赖/不当承诺）         LLM#3(轻量)    ~0.5s
             └ 不可用 → 规则版审计回退（5 类 regex 模式）
  → Step 6b  输出拦截替换（审计告警 → 整段替换安全模板，不走LLM）   Python         <1ms

  安全不变量：任何回复文本必须在 Step 6 + 6b 完整审计后才离开后端
  （SSE 为"先审计、后伪流式"回放，由自动化测试守护，禁止改回真流式）
```

**主动预警（异步触发，5 类）**：

| 预警类型 | 触发条件 | 通知方式 |
|----------|---------|---------|
| 情绪趋势预警 | 近 7 天"心情云"条目 ≥3 条 + 情绪偏负面 | 家长端主动卡片 |
| 异常时段预警 | 22:00-06:00 有对话活动 | 家长端提醒 |
| 沉默预警 | 连续 3 天无对话记录（可能是情绪低落） | 家长端提示 |
| 高风险即时警报 | risk_level = 3（自伤/严重暴力） | 家长端紧急通知 + 12355 热线指引 |
| 使用时长提醒 | 当日累计使用达 2 小时 | 儿童端温暖弹窗（可关闭，不强制锁） |

**为什么重要**：安心童伴不是被动等待孩子发出求救信号，而是从对话模式、情绪趋势、使用行为中**主动发现**潜在风险。这是从"安全过滤器"到"安全 Agent"的关键升级。

### 4.2 重点能力详解

#### 4.2.1 意图理解：确定性规则守底线，LLM 做语义，回退保可用

安心童伴的意图理解采用**规则与 LLM 分工**的架构——确定性规则负责"不可绕过的底线"，LLM 负责"语义理解的天花板"，并在每一层都准备了回退路径。

```
用户输入
    │
    ├─→ Step 1  关键词检测 (Python, <1ms)
    │    · 5 类风险词库, 50+ 关键词模式
    │    · 命中即确定：不依赖任何外部服务，永远不会"幻觉"
    │    · 同时检测家长话题偏好命中（允许/限制/禁止）
    │    · 输出：命中类别 + 置信度
    │
    └─→ Step 2  LLM 风险分类 + 意图识别 (轻量模型, ~1s)
         · 输入：关键词结果 + 用户消息（含近期上下文）
         · 输出：risk_level(0-3) + 话题类别 + mode（故事/百科/情绪/聊天自动识别）
         · LLM 不可用或输出解析失败 → 规则分类器回退：
           仅依据关键词命中与启发式规则给出保守 risk_level
```

**为什么不让 LLM 包办安全判断？**

| | 纯 LLM 方案（行业内常见） | 安心童伴（规则 + LLM 分工 + 确定性拦截） |
|---|---|---|
| 底线拦截 | Prompt 约束，可被绕过/幻觉 | 关键词与策略决策树是代码，不是 Prompt——`risk_level==3` 必然走危机模板 |
| 输出复核 | 无（生成即返回） | 独立批判 Agent 审计，告警即整段替换（Step 6b，确定性规则） |
| 可复现性 | 同一输入每次结果可能不同 | 危机模板/拦截替换/关键词命中完全相同输入→相同输出 |
| 可用性 | API 挂 = 产品挂 | 分类、审计、生成每层均有规则回退，无 Key 也能跑通完整安全闭环 |

**四层兜底保障**：LLM 分类（云端）→ 规则分类器（Python）→ 关键词检测（Python）→ 预置安全模板（危机模板/拦截模板）。每一层都是前一层的安全网，确保在任何环境下都有可用的安全判断机制——这也是 Demo 评审时"无 API Key 仍可完整体验"的实现基础。

**AI 不可替代性说明**：去掉 LLM，系统只剩关键词正则——无法理解"我没事，就是不想说话"里的情绪色彩，无法生成年龄分层的引导式回复，无法做语义级谄媚审计。规则决定"绝不能说什么"，LLM 决定"怎样说才真正帮到孩子"，两者缺一不可。

#### 4.2.2 任务规划：8 种策略的决策引擎

策略引擎根据 risk_level + topic + age + mode 四个变量，从 8 种策略中选择最优响应方式：

| 风险等级 | 策略 | 说明 |
|----------|------|------|
| 0（安全） | 正常儿童友好回复 | 温暖、适龄、鼓励 |
| 0（学习） | 学习引导 | 苏格拉底式提问，不代写作业 |
| 1（轻度） | 情绪陪伴（有边界） | 接住情绪但不无边迎合 |
| 1（AI 依赖） | 防无边迎合引导 | 不附和负面自我认知，引导现实连接 |
| 2（中风险） | 隐私安全引导 / 校园欺凌支持 / 现实连接引导 | 安全回应 + 触发家长提醒 |
| 3（高风险） | **危机模板（不走 LLM）** | 预置安全模板，引导联系家人或拨打 12355 |

**最关键的决策**：risk_level = 3 时，**跳过 LLM 自由生成**，直接使用预置危机模板。这是安心童伴最重要的安全边界——不让大模型在危机情境下"自由发挥"。

#### 4.2.3 记忆能力：三层记忆架构 × 数据最小化

安心童伴的记忆系统采用**三层架构**，在"连贯性"和"隐私"之间找到最优平衡点：

```
┌─────────────────────────────────────────────────────────┐
│                 安心童伴 三层记忆架构                      │
│                                                          │
│  Tier 1 · 工作记忆 (Working Memory)                      │
│  ┌──────────────────────────────────────────────────┐   │
│  │ · 当前会话最近 N 轮对话上下文                       │   │
│  │ · 话题追踪 + 情绪状态实时感知                       │   │
│  │ · 存储：SQLite，per-user 隔离（对话历史可恢复）     │   │
│  │ · 状态：✅ 已实现                                  │   │
│  └──────────────────────────────────────────────────┘   │
│                        │                                 │
│                        ▼                                 │
│  Tier 2 · 情节记忆 (Episodic Memory)                      │
│  ┌──────────────────────────────────────────────────┐   │
│  │ · 每轮对话后自动生成结构化摘要（不存对话原文）        │   │
│  │ · 摘要字段：topics / knowledge_gaps / emotion /    │   │
│  │             socratic_hints / interest_signals      │   │
│  │ · 容量：最近 30 天，滚动过期                        │   │
│  │ · 存储：SQLite，per-user 隔离                       │   │
│  │ · 生成：轻量 LLM（deepseek-chat）线程池异步摘要      │   │
│  └──────────────────────────────────────────────────┘   │
│                        │                                 │
│                        ▼                                 │
│  Tier 3 · 策展记忆 (Curated Memory)                      │
│  ┌──────────────────────────────────────────────────┐   │
│  │ · 孩子主动"种下"的有意义瞬间                        │   │
│  │ · 好奇星 / 心情云 / 探索芽 / 故事册                │   │
│  │ · 永久保留，可随时删除                             │   │
│  │ · 状态：✅ 已实现（小星球）                         │   │
│  └──────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────┘
```

**三层互补关系**：

| | Tier 1 工作记忆 | Tier 2 情节记忆 🆕 | Tier 3 策展记忆 |
|---|---|---|---|
| **谁决定存** | 系统（自动保留 N 轮） | 系统（自动摘要） | 孩子（主动策展） |
| **内容粒度** | 原始对话文本 | 结构化摘要 | 孩子写的标题+内容 |
| **生命周期** | Session 级 | 30 天滚动 | 永久（可删） |
| **隐私风险** | 中（存原文不持久化） | **低（摘要不存原文）** | 极低（孩子控制） |
| **核心用途** | 当前对话连贯性 | **跨会话个性化 + 苏格拉底引导** | 长期成长记录 + 推荐 |

**为什么需要 Tier 2？**

当前架构中，工作记忆只保留最近若干轮对话原文（无结构、无提炼），策展记忆（小星球）依赖孩子主动操作——中间存在一个断层：**系统不知道孩子昨天聊了什么、上周卡在哪里、什么引导方式对他有效。**

Tier 2 填补这个断层，使 LLM 在 Step 4 Prompt 构建时能注入类似这样的上下文：

```
[情节记忆注入]
· 最近 7 天探索的知识主题：天文(3次)、数学(1次)
· 已知理解障碍：对"波长"概念还没完全掌握
· 有效的引导方式：用比喻（上次恐龙比喻效果很好）
· 情绪基线：稳定偏积极
```

**对苏格拉底引导的具体增益**——当孩子问"为什么云是白色的？"，LLM 可以："你记得我们聊过天空为什么是蓝色的吗？那个'光被空气弹开'的想法——云的情况有点不一样，因为云里面的小水滴更大……"——对话有了**知识的连续性**，而不只是孤立的问答。

**隐私设计**：Tier 2 不存对话原文，只存结构化摘要。摘要由轻量 LLM（deepseek-chat）在线程池异步生成（独立数据库会话，不影响主对话延迟），原始对话不进入摘要内容。这是数据最小化原则向中间层记忆的自然延伸。

**Tier 3 策展记忆保留不变**：

四种星球条目类型：
- ⭐ **好奇星**：问题和发现（如"为什么天空是蓝色的？"）
- ☁️ **心情云**：情绪时刻（如"今天考试没考好，但聊完后好多了"）
- 🌱 **探索芽**：**只记录真实世界的行动**（如"我告诉了老师同学推我的事"）
- 📖 **故事册**：和 AI 共创的故事

**探索芽的设计哲学**：系统会校验条目内容是否包含现实行动线索，如果是纯 AI 聊天内容（"和 AI 聊天"），系统会温和提示孩子改为其他类型（校验不过仍会保存，不训斥、不惊吓）。**这让孩子意识到：值得收藏的回忆不在 AI 里，在真实世界里。**

#### 4.2.4 主动服务：从"被动响应"到"主动守护"

| 传统聊天机器人 | 安心童伴 Agent |
|-------------|--------------|
| 等孩子发消息 → 回复 | 除了被动回复，还会主动检查： |
| | · 是不是聊太久了？（2h 弹窗提醒） |
| | · 最近一周情绪怎么样？（情绪趋势检测） |
| | · 这个时间不该睡觉了吗？（深夜使用预警） |
| | · 三天没说话了，还好吗？（沉默预警） |
| | · 上次那个知识还记得吗？（遗忘曲线复习推荐） |

|----|---------|------|
| **前端** | React 18 + Vite + React Router + Framer Motion | 儿童端（主页/聊天/小星球/共创）+ 家长端（仪表盘/告警/偏好/安全引擎演示台） |

| **Pipeline 编排** | `core/` 纯 Python + LLM 混合 | 8 步依序执行，前后端复用，36 项自动化测试守护 |

| **记忆存储** | SQLite 三层（工作/情节/策展） | per-user 隔离；情节记忆不存原文仅存结构化摘要 |
| **部署** | 单进程 8765（可 Nginx/Caddy 反代 HTTPS） | 一键脚本：建库 + seed 演示数据 + 启动 |
| **测试** | pytest × 36 项 | 无 API Key 也全绿；覆盖危机模板/SSE 顺序/拦截/隔离等安全不变量 |

### 5.3 关键技术决策

#### 决策 1：为什么用"确定性规则 + LLM 分工 + 确定性拦截"，而非纯 LLM 做安全？

传统做法是让一个 LLM 同时输出安全判断和对话回复——但 LLM 会幻觉，可能被 prompt injection 绕过，且每次输出不稳定。安心童伴的选择是**底线交给代码，天花板交给 LLM**：

| 对比维度 | 纯 LLM 安全方案 | 安心童伴（规则 + LLM 分工 + 确定性拦截） |
|---------|----------------|----------------------------------------|
| 底线拦截 | LLM 内嵌，Prompt 层面约束 | 关键词检测 + 策略决策树 + 拦截替换，全部是代码而非 Prompt |
| 危机场景 | LLM 自由发挥，输出不可控 | `risk_level==3` 必然走预置危机模板，确定性、可复现 |
| 输出复核 | 无（生成即返回） | 独立批判 Agent 审计；告警 → Step 6b 整段替换（不走 LLM 再生成） |
| 流出纪律 | 流式即生成即流出 | SSE 先完整审计、后伪流式回放（测试守护的架构不变量） |
| 可用性 | API 挂 = 产品挂 | 分类/审计/生成每层均有规则回退，无 Key 可跑通完整闭环 |

**设计逻辑**：安全底线需要确定性、可审计、不可绕过——这是规则的优势；语义理解和有温度的引导需要灵活性、深度——这是 LLM 的优势。Pipeline 让两者各守其位，并用"先审计、后流出"把出口焊死。

#### 决策 2：为什么用双模型而非单模型？

| 场景 | 模型 | 理由 |
|------|------|------|
| 风险分类（Step 2） | deepseek-chat（轻量） | 只需结构化分类输出，用小模型省延迟省成本 |
| 回复生成（Step 5） | deepseek-v4-pro（主模型） | 儿童对话需要高质量、有温度的回复 |
| 批判审计（Step 6） | deepseek-chat（轻量） | 独立调用审计，避免生成模型的 Self-evaluation Bias |
| 情景摘要（Tier 2） | deepseek-chat（轻量） | 线程池异步执行，不占主对话延迟 |

同一厂商双档位，依赖明确、成本可控：每轮对话 1 次主模型 + 最多 2 次轻量模型调用。

#### 决策 3：为什么危机情况下不走 LLM？

risk_level = 3（自伤/自杀/严重暴力）时，Step 3 策略引擎直接跳过 Step 4-5（Prompt 构建 + LLM 生成），使用预置的危机模板：

> "你现在一定很难过，谢谢你愿意告诉我。你不是一个人，身边有人愿意帮你——请立即告诉爸爸妈妈、老师，或者拨打 12355 青少年服务热线（24 小时）。有些感受说出来会好一点，找你信任的大人聊一聊好吗？"

**设计逻辑**：在最高风险场景下，信任预置的安全模板 > 信任 LLM 的自由生成。这不是技术能力问题，是安全边界设计。

#### 决策 4：为什么记忆系统用三层而非单层？

纯"对话历史"方案的问题：session 关闭后知识全部丢失，没有积累。纯"策展记忆"方案的问题：依赖孩子主动操作，覆盖率太低（孩子可能几天不种一颗星），LLM 在跨会话场景下是"失忆"的。

安心童伴的三层方案：

| | 工作记忆 (Tier 1) | 情节记忆 (Tier 2) | 策展记忆 (Tier 3) |
|---|---|---|---|
| **内容** | 最近 N 轮对话原文 | 结构化摘要（topic + gap + emotion） | 孩子策展的星球条目 |
| **生成方式** | 自动保留 | 每轮后轻量 LLM 异步摘要 | 孩子主动"种" |
| **生命周期** | 会话级（可恢复） | 30 天滚动 | 永久 |
| **隐私** | per-user 隔离存储 | **摘要不存原文（数据最小化）** | 孩子控制 |
| **解决什么问题** | 当前对话连贯 | 跨会话个性化 + 苏格拉底引导 | 长期成长记录 |

**Tier 2 是关键创新**：在"全自动记忆（隐私风险高）"和"全手动记忆（覆盖率低）"之间找到第三条路——系统自动生成轻量摘要，但不保存对话原文。这既保证了 LLM 的跨会话个性化能力，又延续了数据最小化的设计哲学。

#### 决策 5：为什么记忆系统用策展式而非全自动？（Tier 3 的设计理由）

| 全自动记忆 | 策展式记忆（安心童伴） |
|-----------|---------------------|
| 系统偷偷记住所有对话 | 孩子主动选择保存什么 |
| 隐私风险高 | 天然符合数据最小化（《个保法》要求） |
| 噪声多（大量无关对话） | 信号强（只保留孩子觉得重要的） |
| AI 引用时容易突兀 | AI 引用时自然（孩子自己存的，当然相关） |

#### 决策 6：为什么从 Streamlit 原型重构为 React + FastAPI 全栈？

早期原型用 Streamlit 快速验证了 Pipeline 架构。当架构稳定后，我们按计划重构为 React 18 + FastAPI + SQLite 的 v2.1 全栈版，原因：

| 考量 | 说明 |
|------|------|
| **真实用户体验** | 儿童产品需要精细的交互动效（生命树生长、破壳粒子、SSE 决策链回放），Streamlit 组件模型做不到 |
| **多角色多页面** | 儿童端 + 家长端双前端、JWT 认证、per-user 数据隔离——需要正式的 Web 架构 |
| **核心零重写** | `core/` Pipeline 为纯 Python 模块，重构前后两端复用，一行核心逻辑未改——验证了"架构分层不绑定框架"的原始设计 |
| **可测试性** | 重构同时补齐 36 项 pytest，把安全不变量（SSE 顺序/危机模板/拦截替换）钉死在 CI 里 |

Streamlit 旧版保留为兜底演示通道，主线为全栈版。

#### 决策 7：为什么 spike 验证后主动弃用本地安全小模型（Qwen3Guard）？

我们曾对通义千问 Qwen3Guard-Gen-0.6B（GGUF 本地推理）做过完整 spike 验证（见《Qwen3Guard-spike验证报告》），结论：**不接入 Pipeline**，原因：

- **收益不抵开销**：0.6B 安全小模型在中文儿童语境的增量判断，与"关键词规则 + LLM 分类 + 批判审计"现有组合高度重叠；引入 llama.cpp + GGUF 模型文件则增加数百 MB 部署体积与 CPU 常驻开销；
- **确定性已有更便宜的来源**：危机模板、关键词检测、拦截替换都是零成本确定性机制，安全底线不依赖概率模型；
- **依赖明确性**：弃用后全部外部依赖只剩 DeepSeek 一个 API，部署与复现路径对评委完全透明（无 Key 也可跑规则回退模式）。

这条决策链（spike → 数据 → 弃用）本身就是"技术可行性"维度的证据：**资源开销可控、对外部依赖明确**——我们不堆砌技术，只保留能通过验证的东西。

### 5.4 8 步安全 Pipeline 详解

安心童伴的每一次对话都完整经过 8 步 Pipeline。它不是"过滤器外挂"，而是**对话的主流程本身**——不跑完这 8 步，孩子看不到任何回复。

```

                        │    用户输入 / LLM 输出     │
                        └────────────┬─────────────┘
                                     │

        │   ║          · per-user 隔离，跨账号不可见            ║  │
        │   ║                                                  ║  │
        │   ║  Step 1  关键词检测    Python re   <1ms          ║  │
        │   ║          · 5类风险，50+模式（确定性，非概率）     ║  │

        │                            ▼                            │
        │   ╔══════════════════════════════════════════════════╗  │
        │   ║         第二程 · 决策与生成（Step 3-5）           ║  │
        │   ║                                                  ║  │
        │   ║  Step 3  策略决策树    Python      <5ms          ║  │

        │   ╔══════════════════════════════════════════════════╗  │
```

**三程互补关系**：

| | 第一程 输入过滤 | 第二程 决策与生成 | 第三程 输出复核与拦截 |
|---|---|---|---|
| **执行时机** | 生成前 | 生成中 | 流出前 |
| **核心方法** | 关键词 + LLM 分类（规则回退） | 策略树 + 年龄分层 Prompt + 主模型 | 批判审计 + 确定性拦截替换 |
| **解决的问题** | 识别危险输入并定级 | 给出有温度、有边界的回复 | 不让任何未审计文本触达孩子 |
| **失败模式** | 新颖表达漏判 → 由第三程兜住 | LLM 不可用 → 脚本回退模式 | 模板化回复不够个性（可接受的安全代价） |
| **外部依赖** | LLM（可选，规则可独立运行） | LLM（主模型） | LLM（可选，规则版审计可独立运行） |

**兜底路径（所有 LLM 不可用时）**：规则分类器 + 规则版审计 + 8 种策略 × 4 种模式的预置回退回复——产品降级但安全闭环完整。演示与评审环境无需任何 API Key 即可复现完整流程（界面明确标注为降级模式）。

### 6.2 主模式：B2B2C 教育机构合作

**逻辑**：在线教育机构（猿辅导、作业帮、学而思等）在《拟人化办法》新规下面临合规压力——他们需要植入合规的儿童 AI 交互能力。安心童伴的 8 步安全 Pipeline（纯 Python 核心模块，框架无关）可以作为"儿童 AI 安全中间件"授权给教育平台。

**收入模式**：
- API 调用量计费（按 Pipeline 运行次数）
- 年度授权费 + 定制化集成服务

**为什么这个路径可行**：
- 教育机构有现成的儿童用户群，无需安心童伴自己获客
- 合规是教育机构的刚需（《拟人化办法》监管压力），付费意愿强
- 纯软件集成，不涉及硬件适配，落地周期短

### 6.3 辅助模式：B2C 家长订阅

**逻辑**：面向有 AI 安全意识的高知家长群体，提供安心童伴的完整功能。

**定价策略**：
- 基础版（免费）：语音聊天、百科问答、故事陪伴、基础安全检测
- Premium（¥29/月或 ¥199/年）：学习引导、内容推荐、家长周报、主动预警、话题偏好精细控制

### 6.4 市场切入点

**第一阶段**（当前）：SpaceMind 大赛验证产品概念 → 获得讯飞生态资源对接机会
**第二阶段**（6 个月）：与 1-2 家教育机构合作集成 → 验证 B2B2C 模式
**第三阶段**（12 个月）：开放 API → 扩展至智能设备厂商（学习机、儿童手表等）
**第四阶段**（18 个月）：发布家长端独立 App → 直接面向 C 端

### 6.5 竞争优势的可持续性

**为什么大厂不会轻易复制我们的核心能力？**

- **工程化的安全 Pipeline**：大厂的儿童 AI 产品普遍使用"LLM 内嵌安全 Prompt"方案——同一模型既做安全判断又做对话生成，Prompt injection 可绕过。安心童伴把底线交给代码：关键词检测、策略决策树、危机模板、拦截替换、SSE"先审计后流出"，每一环都是确定性机制，并有 36 项自动化测试守护不变量。大厂要复制需要重构整个对话主流程而非加几行 Prompt——改动成本从分钟级变为周级。
- **反谄媚机制**：要求 AI 主动不讨好用户——这与商业产品的"用户留存"逻辑天然冲突。大厂产品经理很难推动一个"故意降低用户粘性"的功能。
- **合规先发优势**：安心童伴从 Day 1 就按合规设计，大厂需要从现有架构中剥离不合规功能再重建——时间窗口约 6-12 个月。
- **策展式记忆**：数据最小化虽然合规，但也意味着无法像大厂那样用全量数据做推荐——这是一个"价值观驱动的产品取舍"，不是技术差距。

### 7.1 战略主线：一种架构，两种价值表达

安心童伴的双核（8 步安全 Pipeline × 策展式记忆）不变，但在两个年龄段表达不同价值：

- **5-10 岁是「陪伴 + 保护」**——已成熟落地（语音/故事/小星球/学习引导/共创）；
- **11-14 岁是「赋能 + 自主」**——这是下一阶段的重心。用户研究指出青少年的四大功能空白：

| 空白 | 含义 | 我们的回应（见下方路线） |
|------|------|------------------------|
| 隐私自主 | 青少年抗拒"被监控感"，家长控制类 App 因此大量一星差评 | 三档可见性（已上线）+ 条目级选择性分享（P0 做深） |
| 身份探索（最核心） | 青少年在找"能反馈『你是谁』的镜子"，现有功能只能反馈"你做了什么" | 「我的成长日记」（P1 第一顺位）→ 身份星图（P3） |
| 创意表达 | 探索/改造类创意动机缺少承接出口 | AI 漫画工坊（P2，共创故事是现成输入） |
| 审美适配（最直观） | 卡通 UI 让青少年"第一眼就走掉" | UI 去幼稚化、分龄渲染（P0） |

**排序原则：先把现有东西改对，再补缺失功能**——否则青少年会因幼稚 UI 和被监控感第一眼离开，任何新功能都无人使用。

### 7.2 P0 加固期（0-2 周）：先修安全、再改对现有

| 项 | 说明 | 状态 |
|------|------|------|
| 安全不变量修复 | 关键词确定性命中给 `risk_level` 设下限，LLM 只能抬高不能压低；含 2 条回归测试（"我想自杀"类输入在任何 LLM 状态下必触发危机模板） | ✅ **已完成（2026-08-14，36 项测试全绿）** |
| 分龄 Prompt 四档深化 | 11-13"酷 mentor"、14+"可信赖老友"的语言风格做深 | 📐 设计就绪（`age_tiers` 已四档化） |
| UI 去幼稚化 | 小星球低龄"星球花园"卡通向 / 高龄"成长轨迹"分龄渲染 | 📐 设计就绪（前端主题层） |
| 青少年选择性分享 | 三档家长可见性已上线；补条目级分享控制 | 📐 共创故事 `shared_with_parent` 已验证链路 |
| 推荐引擎互动卡片 | 后端推荐已就绪，前端补可交互卡片 | 📐 设计就绪 |

### 7.3 P1 冲刺期（入围决赛后）：补青少年缺失

| 项 | 说明 | 状态 |
|------|------|------|
| **我的成长日记**（第一顺位） | AI 引导青少年复盘一天，生成结构化成长记录——命中"身份探索"空白（学界 Mirror「镜中人」原型已验证该方向），同时强化策展记忆双核 | 📐 设计就绪，约 1.5 天（三层记忆架构已预留数据模型扩展位） |
| 时间胶囊"回信给过去的我" | 破壳时 AI 以"过去的自己"口吻回信，仅改交互方向 | 📐 设计就绪，约 1 天 |
| 11-14 青少年内测 + 决赛路演 | 验证隐私可见性与身份探索的正向反馈 | 📐 计划 |

### 7.4 P2 产品化期（赛后 3-9 月）：合规窗口双线 PMF

- **B2C 家长订阅内测** + **B2B 试点 2-3 家**（教育机构/硬件厂商），双轮验证第六章商业模式；
- **AI 漫画工坊**（💡 需图像生成 API，先评估内容审核与成本；共创故事成品是现成输入）——承接青少年"创意表达"空白；
- **家庭约定**（💡 概念方向）：家长与孩子共定使用约定，系统温和执行——话题偏好机制是其已验证子集；
- **Pipeline 抽离为可独立部署模块**，为 P3 的 SDK/API 化做工程准备。

### 7.5 P3 标准化期（9-18 月+）：SpaceMind 生态与行业标准

- **家庭终端落地**：经讯飞语音 + SpaceMind 双路由架构接入故事机、家庭屏、儿童手表——安心童伴作为家庭空间里的"儿童陪伴 Agent 层"，感知层从浏览器延伸到房间（讯飞语音 SDK 已完成 spike 验证）；
- **安全中间件开放**：8 步 Pipeline 核心（`core/`）为框架无关的纯 Python 模块，封装为"儿童 AI 安全中间件"以 SDK/API 交付——可集成、可审计，卡位儿童 AI 安全标准；
- **身份星图**：基于策展记忆/成长日记/胶囊的长期积累，生成孩子的兴趣与成长画像（数据积累足够后启动；坚持"摘要不存原文"的数据最小化纪律）；
- **儿童 AI 安全标准/认证**：以危机模板、先审计后流出等确定性机制为蓝本参与行业实践。

### 7.6 Non-goals 与规划纪律

**明确不做**：
- 短期不做：5-7 低龄语音专项（解决的是低龄短板而非当前的青少年短板）、身份星图（数据门槛高，归入 P3）；
- 长期不做：任何"替代真实人际关系"的陪伴角色——尤其**不正面接管青春期"虚拟亲密关系"**（高危合规地带，行业已有血泪案例），安心童伴只做"风险信号对家长可见"。

**规划可信的三个理由**：
1. **主线不稀释**：每个新功能必须强化"安全有边界的交互 × 策展记忆"双核，否则不做；
2. **合规先行**：新功能先过 §10.3 合规对照表再开发；
3. **每次规划都有前例**：共创故事从搁置清单到上线走完了"调研 → 决策矩阵 → 落地 → 测试"全流程；P0 第一项（安全不变量修复）从发现到带回归测试上线不足一天——本章条目复用同一决策与执行机制。

## 第十章 · 隐私与安全设计

### 9.1 数据最小化原则

| 数据类型 | 存储方式 | 保留期限 | 说明 |
|----------|---------|---------|------|
| 对话消息 | SQLite（自托管，per-user 隔离） | 用于会话恢复与上下文 | 仅当前账号本人可见；单文件库，部署者自持数据，可整体删除 |
| 情景记忆摘要 | SQLite（per-user 隔离） | 30 天滚动过期 | 只存结构化摘要（话题/情绪/引导线索），**不含对话原文** |
| 星球记忆条目 | SQLite（per-user 隔离） | 孩子可随时删除 | 仅存孩子主动策展的内容；信任模式（14+）家长端不可见星球概览 |
| 共创故事 | SQLite（per-user 隔离） | 默认仅孩子可见 | 孩子主动分享后家长端才可见（shared_with_parent） |
| 家长告警/摘要 | SQLite（per-family 隔离） | 长期 | 脱敏后的统计摘要，不展示对话原文 |

### 9.2 家长可见性分级

| 年龄段 | 家长可见内容 | 家长不可见内容 |
|--------|------------|--------------|
| 5-7 / 8-10 岁（守护模式） | 每轮主题摘要、风险提醒、使用统计、星球概览 | 对话原文 |
| 11-13 岁（过渡模式） | 周度摘要、高风险事件即时提醒 | 对话原文、星球内容（默认私密，孩子选择分享的除外） |
| 14 岁及以上（信任模式） | 高风险事件提醒（仅在风险等级 ≥2 时） | 对话原文、星球概览、日常话题统计 |

### 9.3 合规对照

| 法规要求（《拟人化办法》） | 安心童伴状态 |
|--------------------------|------------|
| 禁止诱导不安全行为 | ✅ 已覆盖：8 步 Pipeline 多层拦截 + 危机模板确定性返回 |
| 禁止虚拟亲密关系 | ✅ 已覆盖：反谄媚 Prompt + 批判审计 + "不替代真人"原则 |
| 监护人同意 | ✅ 已覆盖：注册强制勾选，前后端双校验 |
| 未成年人模式 | ✅ 已覆盖：四年龄档三模式（5-7/8-10 守护、11-13 过渡、14+ 信任） |
| 年龄识别 | ✅ 已覆盖：注册时选择年龄档（儿童账号必填） |
| AI 身份标识 | ✅ 已覆盖：聊天页常驻 AI 身份徽章 + Prompt 声明 + 主页/落地页页脚声明 |
