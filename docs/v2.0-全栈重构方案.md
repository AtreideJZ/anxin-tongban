## Context

当前 Demo 基于 Streamlit 构建，已完成安全引擎（10 步 Pipeline，含 Step 1b/6c Qwen3Guard 融合代码）、三层记忆系统、双模型策略等核心架构。但 Streamlit 的天花板已经严重制约产品发展：

- **动画/游戏化无法实现**：成长树、星球全景、时间胶囊破壳动画等在 Streamlit 中只能降级为静态卡片
- **状态模型与产品脱节**：`st.session_state` 按浏览器 Tab 分配，无用户系统，无法持久化
- **大量「假功能」**：守护/信任模式无实际差异、四种对话模式手动选择形同虚设、家长端设置只是展示面板
- **Demo 数据泄露到正式产品中**：`planet.json` 写死 8 条演示数据

同时，SpaceMind 大赛初赛提交截止 **8 月 14 日 17:00**（剩余 15 天）。注意：初赛为**闭门文档评审**，方案书（PDF/PPT）是唯一**必选**提交物，demo / 代码 / 视频为加分材料——时间分配必须同时覆盖「工程」与「提交物」两条线。评分中 **功能完整性 25 分 + 创新性 20 分 + 场景价值 20 分** 占比最高。

## 第二部分：技术选型分析

### 2.1 最终技术栈

```
┌─────────────────────────────────────────────────┐
│                  前端 (React)                    │
│  React 18 + React Router + CSS Modules          │
│  + Framer Motion (动画)                          │
│  + Recharts (家长端图表)                          │
│  + Web Speech API (语音识别 + TTS, 浏览器内置)    │
├─────────────────────────────────────────────────┤
│                后端 (FastAPI)                    │
│  FastAPI + Uvicorn                               │
│  + SQLAlchemy + SQLite                           │
│  + python-dotenv (配置)                          │
│  + 保留全部 core/ 模块（零改动或微小改动）          │
│  + FastAPI 直接托管前端 vite build 产物（单进程）  │
├─────────────────────────────────────────────────┤
│                AI 模型层                          │
│  DeepSeek v4-pro (主回复，流式)                   │
│  deepseek-chat (轻量分类/审计/摘要，非流式)        │
│  Web Speech API (语音, 浏览器内置, 免安装)        │
└─────────────────────────────────────────────────┘
```

### 2.2 为什么选这套技术栈

| 维度 | Streamlit（当前） | React + FastAPI（目标） |
|------|------------------|------------------------|
| UI 灵活度 | 极低 — 只能渲染静态 HTML 字符串 | 极高 — 任意动画、游戏化、组件复用 |
| 成长可视化 | 做不到（4 个 div 模拟） | Framer Motion 做一棵真正的动画树 |
| 状态管理 | `st.session_state`（单 Tab） | SQLite（持久化、多用户） |
| 用户体验 | 仪表盘感，无过渡动画 | 儿童产品应有的温暖交互 |
| 大赛评审印象 | 「又一个 Streamlit Demo」 | 「完整的前后端分离产品」 |
| 部署 | streamlit.io（国内访问不稳，已踩过坑） | **国内轻量云服务器**（见下） |
| 开发效率 | 高（Python 一把梭） | 中（前后端分离，AI 编程加持下压缩明显） |

**部署选型修正（v2.1）**：放弃 Vercel + Railway——两者在大陆访问不稳定，讯飞及国内评委大概率打不开（README 里 Streamlit Cloud "唤醒慢或跳转登录" 的坑不能换个平台再踩一次）。改为：

- **一台国内轻量云服务器**（阿里云 / 腾讯云均可），FastAPI 直接托管 `vite build` 产物——单进程、单机器、零 CORS，部署复杂度反而低于双端 PaaS
- **兜底一**：README 保证 clone 后 3 步本地跑通（继承现有 Streamlit 版的优点，技术评委会看）
- **兜底二**：演示视频（部署全挂也不影响评审）

### 2.3 为什么 SQLite 而不是 PostgreSQL

- 大赛阶段只需单机运行，SQLite 零配置、零运维
- 比赛评委可以直接 clone + `pip install` + `python main.py` 跑起来
- SQLAlchemy ORM 保证后续可以无缝切换到 PostgreSQL
- 不需要 Docker、不需要云数据库

### 3.2 API 设计（核心端点）

```
POST   /api/auth/register           # 注册（用户名 + PIN + 年龄档位 + 角色 + 监护人同意勾选）
POST   /api/auth/login              # PIN 码登录 → JWT token

GET    /api/chat/history            # 获取聊天历史
POST   /api/chat/send               # 发送消息 → SSE 事件流（见 4.5，非真流式）
  Body: { "message": "..." }
  Response: text/event-stream
    event: step   → Pipeline 步骤事件（安全引擎可视化）
    event: token  → 审计通过后的回复切块（伪流式）
    event: done   → 推荐卡片 + 星球建议 + 每日挑战 + 决策记录

GET    /api/planet/entries          # 获取星球条目列表

GET    /api/planet/weather          # 获取星球天气

GET    /api/capsules                # 获取胶囊列表
POST   /api/capsules                # 创建胶囊
DELETE /api/capsules/{id}           # 删除胶囊

GET    /api/parent/dashboard        # 家长仪表盘数据（风险趋势+使用时长+话题分布）
GET    /api/parent/alerts           # 家长告警列表
GET    /api/parent/emotion-trend    # 7天情绪趋势
PUT    /api/parent/preferences      # 更新话题偏好（真正生效）
GET    /api/parent/planet-overview  # 星球概览（计数，8-11岁可见）

```

### 3.3 数据流（v2.1 修正版）

```
用户输入 → React (fetch + SSE 解析)
         → FastAPI /api/chat/send
         → chat_service.py → 线程池执行 core.pipeline.run()
           · Pipeline 完整执行：Step 0 → 1 → 1b → 2 → 3 → 4 → 5 → 6 → 6c → 6b
           · 【安全不变量】任何 token 在通过 Step 6/6c 审计前不得离开后端
           · Step 6b 拦截时，SSE 只输出替换后的安全模板
         → SSE 事件序列：
           1. step 事件：Pipeline 各步骤（驱动家长端安全引擎可视化逐步点亮）
           2. token 事件：审计通过的 final_reply 切块伪流式推送（打字机效果）
           3. done 事件：推荐卡片 + 星球建议 + 每日挑战 + 决策记录
         → React 渲染气泡 + 打字动画

         → episodic_memory 摘要（已含在 pipeline 内）→ SQLite
         → 异步：proactive_engine.run_checks() → 家长告警队列
```

## 第四部分：关键设计决策

### 4.1 统一对话模式（不再手动切换）

当前四种模式（聊天/故事/百科/情绪）需要手动选择，体验割裂。

**v2.1 方案**：一个对话框，AI 自动识别意图并切换内部策略。

```
用户："恐龙为什么会灭绝？"
  → Step 2 识别 topic=encyclopedia_question, mode=encyclopedia
  → Step 3 选择 strategy=socratic_learning_guide
  → Step 4 注入百科模式 prompt + 苏格拉底式引导规则
  → 用户不需要知道「模式」的存在

用户："今天同学把我的书扔到了地上"
  → Step 1 关键词命中 bullying
  → Step 3 选择 strategy=bullying_support
  → 自然进入「情绪树洞 + 欺凌支持」混合模式
```

**实现**：删除侧边栏的模式选择 radio。`mode` 参数不再由用户选择，而是在 Pipeline Step 2 中由 LLM 自动判断并存储在会话上下文中。下一个对话轮次使用前一轮的上下文模式。

> ⚠️ **注意（v2.1 补充）**：`risk_classifier.classify()` 目前只输出 topic + risk_level，**不输出 mode**。需要给分类器增加 mode 字段输出（小改动，但方案不能当作零成本）。

### 4.5 SSE 与安全审计：先审计、后伪流式【v2.1 核心修正】

v2.0 的数据流写的是 `pipeline.run() → 逐 token yield (SSE stream)`——这与安全审计架构**直接冲突**，必须修正。

**冲突在哪**：现有 Pipeline 的安全闭环是"先审计、后展示"：

- `pipeline.py:468-476` 先收集全部 token 拼成 `final_reply`
- Step 6 批判审计（`pipeline.py:509`）+ Step 6c Qwen3Guard 复核（`:526`）
- Step 6b 可**整段拦截替换**（`:554-557`）

如果真流式逐 token 推送，孩子已经看到内容，Step 6/6c/6b 全部失效——不可能撤回已渲染的字。对一个把"输出双审 + 拦截替换"写进方案书当核心卖点的产品，这是架构级倒退。

**v2.1 方案：服务端伪流式**。

1. Pipeline 在线程池中**完整跑完**（含双审和可能的拦截替换）
2. SSE 按序推送三类事件：
   - `step`：Pipeline 步骤事件 → 前端安全引擎决策链逐步点亮（换栈才能拿到的加分项：Streamlit 做不到的实时可视化）
   - `token`：审计通过的 `final_reply` 按 3-4 字切块推送 → 打字机效果
   - `done`：推荐卡片 + 星球建议 + 每日挑战 + 决策记录
3. **安全不变量（写进测试）**：任何 token 在通过 Step 6/6c 审计前不得离开后端；触发拦截的输入，前端只能收到替换后的安全模板

**实现要点**：
- MVP 简化：Pipeline 跑完后按序回放 step 事件（带小延时）再推 token——实现成本≈0，视觉效果与实时一致
- 增强（可选）：给 `pipeline.run()` 加可选 `on_step` 回调（默认 None，现有行为不变），step 事件真实时
- 打字机 UX 与 v2.0 承诺完全一致，安全性质零损失——这正是当前 Streamlit 版 `stream_reply()` 的做法，只是搬到了 SSE 上

### 4.6 Qwen3Guard 真实加载 spike【v2.1 升级】

### 10.3 Qwen3Guard 移除（2026-08-03 核心架构修订）

**移除理由：**

- 0.6B 模型增加每次对话 ~500-800ms 延迟，但关键高危输入（"我不想活了"）被判 Safe
- 对"我想自杀"判 Unsafe，但对"我想死"/"我活不下去了"仅判 Controversial——一致性差
- 安全闭环已由**三层接力**覆盖：关键词检测（Step 1, 确定性规则）→ LLM 风险分类（Step 2, 语义深度）→ 批判 Agent 审计（Step 6, 输出校验）
- 专用安全模型的"N+1 保障"理念正确，但实际 0.6B 量化版在中文儿童语境下性能不满足演示要求

**影响：**

- Pipeline 从 10 步（0→1→1b→2→3→4→5→6→6c→6b）精简为 8 步（0→1→2→3→4→5→6→6b）
- 移除 Step 1b（Qwen3Guard 输入审核）和 Step 6c（Qwen3Guard 输出复核）
- Step 6b 触发条件从"语义审计 OR 安全标签审计"简化为"语义审计"
- `core/qwen_guard.py` 保留代码但标注弃用
- `models/` 下 GGUF 文件和 `scripts/download_qwenguard.py` 保留不删（后续如需要可恢复）

**安全性质不变：** "我不想活了" 仍由 Step 1 自伤关键词命中 → risk_level=3 → 危机模板（不走 LLM 自由生成）。这个确定性安全阀不依赖任何概率模型。

### 10.4 当前 Pipeline 架构（v2.1-final，8 步）

```
用户输入
  │
  ▼
┌─────────────────────────────────────────────┐
│ Step 0  记忆检索                    Python  │
│         策展记忆(Tier3) + 情节记忆(Tier2)     │
│         输出：合并后的记忆上下文              │
├─────────────────────────────────────────────┤
│ Step 1  关键词检测                  Python  │
│         5 类本地规则库 + 家长话题偏好         │
│         输出：命中类别 / 置信度 / 偏好命中    │
├─────────────────────────────────────────────┤
│ Step 2  风险分类                     LLM #1 │
│         LLM 语义理解，判定 topic + risk_level │
│         + 对话模式 mode（方案 4.1）           │
│         输出：RiskClassification            │
├─────────────────────────────────────────────┤
│ Step 3  策略决策                    Python  │
│         纯 Python 决策树，按 risk+topic+age  │
│         +mode 选择 7 种策略之一              │
│         risk=3 → 危机模板(跳过 4/5/6)        │
├─────────────────────────────────────────────┤
│ Step 4  Prompt 构建                 Python  │
│         年龄基础 + 模式规则 + 反谄媚          │
│         + 策略指令 + 记忆上下文 + 文化元素     │
├─────────────────────────────────────────────┤
│ Step 5  回复生成                     LLM #2 │
│         主回复模型流式生成候选回复            │
├─────────────────────────────────────────────┤
│ Step 6  批判 Agent 审计              LLM #3 │
│         事后整段审计：谄媚/依赖/不当引导      │
│         输出：CriticResult（alert + issue）  │
├─────────────────────────────────────────────┤
│ Step 6b 输出拦截替换                Python  │
│         critic.alert → 替换为 SAFE_TEMPLATE  │
│         确定性安全阀，不走 LLM 再生成         │
└─────────────────────────────────────────────┘
  │
  ▼
最终回复（通过审计 / 已被安全模板替换）
```

**安全闭环三层接力（替代 Qwen3Guard 的 N+1）：**

| 层级 | 步骤 | 类型 | 捕捉范围 |
|------|------|------|---------|
| 确定性规则 | Step 1 关键词 | Python 本地 | 自伤/欺凌/隐私/不适龄/AI依赖——命中即生效，不走概率 |
| 语义深度 | Step 2 LLM 分类 | LLM | 关键词漏网的隐含风险（如委婉表达、语境依赖） |
| 输出校验 | Step 6 批判审计 | LLM | 已生成回复中的谄媚/依赖/不当引导——事后兜底 |

**Step 6b 确定性安全阀：** 批判 Agent 告警后不调用 LLM 修正，直接替换为 `SAFE_REPLACEMENT_TEMPLATE`。避免"修复生成"引入新风险——这一步是**规则**，不是建议。
