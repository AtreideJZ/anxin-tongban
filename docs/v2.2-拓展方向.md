## 四、亲子话题卡 B 细则（约 1 天）

### 4.1 功能

聊天页底部加一个独立按钮/入口："💬 想和爸爸妈妈聊点什么？"。点击后 AI 生成一个温暖的话题提示（如"今天学校里最让你笑的一件事是什么？""如果你可以发明一样东西，会是什么？"），孩子拿着这个去和父母面对面聊。

### 4.2 技术落点

- **后端**：`backend/routes/cocreation.py` 新增 `POST /api/cocreation/topic`，调用轻量 LLM 生成一个话题。Prompt 模板：年龄适配 + 避免敏感话题 + 引导正向亲子交流
- **前端**：`ChildrenChat.jsx` 输入区增加一个话题按钮；点击后显示话题卡片（可刷新）
- **不计入使用时长**：话题卡不走 `chat/send`，是亲子活动引导，不触发 usage_minutes 计数
- **测试**：验证生成的 topic 不含敏感词、年龄适配

## 五、共创故事 C 细则（约 1.5 天）

### 5.1 完整流程

```
孩子在小星球页点"+ 共创故事"
  → AI 生成开头（一段，30-50字），留白等待
  → 孩子接一段
  → AI 轻量引导（"接下来会发生什么？"），不代写
  → 家长接一段（同设备轮流；异步场景：家长可留"素材"）
  → AI 串联润色（语法/错别字，不改变情节和表达）
  → 成品展示，标注「✍️ 宝宝和爸爸一起写的故事」
  → 自动种星球 📖故事册
```

### 5.2 技术落点

| 组件 | 说明 |
|------|------|
| **数据模型** | `cocreation_stories` 表：id, child_user_id, parent_user_id, title, turns (JSON: [{role, content, ts}]), final_text, created_at |
| **后端** | `backend/services/cocreation_service.py`：start / add_turn / finalize |
| **路由** | `backend/routes/cocreation.py`：POST /api/cocreation/story/start, POST /api/cocreation/story/turn, POST /api/cocreation/story/finalize |
| **前端** | 新页面或小星球内嵌表单（视 UX 定） |
| **安全** | 孩子的输入仍走完整 Pipeline（`cocreation_service` 调用 `pipeline.run()` 审计每一段）；AI 的串联润色输出走 Step 6 审计 |
| **隐私** | 成品默认孩子私密；孩子主动点"给爸爸妈妈看"后家长端可见。当面同设备共创时家长自然在场，不触发推送 |
| **演示** | `seed.py` 为 demo_kid 预置一篇完成的共创故事，含共同作者标注 |

### 5.3 设计原则（硬规则）

1. AI 是脚手架，不替孩子写情节——只引导、串联、改错别字
2. 每段孩子输入仍走完整 Pipeline——共创路径不得绕过安全闭环
3. 共用设备轮流输入，不另建实时同步——v2.1 方案 4.10 原话"同一设备轮流输入"
4. 成品标注共同作者（Authenticity）
5. 共创不计入 2 小时使用计时（亲子活动，不是 AI 使用）

### 5.4 分龄差异

- **5-10 岁**：AI 多引导（"你觉得接下来会发生什么？"），故事更短（3-4 轮）
- **11-14 岁**：孩子主导，家长退后；AI 只做最小干预；故事可更长

## 六、讯飞语音 SDK spike D 细则（≤1 天，硬时限）

### 6.1 目标

验证讯飞语音 SDK 在浏览器端的可用性：中文儿童语音识别准确率是否显著优于 Web Speech API，TTS 音色是否更适龄。

### 6.2 验证步骤

1. 注册讯飞开放平台，获取 APPID/APIKey/APISecret
2. 测试实时语音识别（流式 WebSocket）→ 对比 Web Speech API 准确率差异
3. 测试 TTS 音色 → 对比浏览器 speechSynthesis 的自然度差异
4. 评估密钥安全方案：前端直连暴露凭证 → 需后端代理或临时凭证签发
5. 评估集成复杂度 → 是否能 ≤0.5d 替换到 VoiceButton

### 6.3 判定标准与兜底

| 结果 | 行动 |
|------|------|
| 全部通过且集成可行 | 替换 VoiceButton + useVoice 为讯飞方案，标注正式版已接入 |
| 部分通过（如 TTS 好但 ASR 差） | 混合方案：ASR 用 Web Speech、TTS 用讯飞；或全部保留 Web Speech |
| spike 失败（注册问题/鉴权复杂/准确率无优势） | 回退 Web Speech，保留 Demo 级标注（方案 4.7 叙事不变） |

**底线纪律：失败零代价。** 与 Qwen3Guard spike 同——Web Speech 路径已经是可用的交付物。
